### Focus 重连修正

- 全零、无有效状态的 idle `FOCUS_STATE` 不再触发 `FOCUS_RESOLVE`。
- `FOCUS_RESOLVE` 返回 `INVALID_STATE` 时，只重新执行一次完整的 `QUERY → STATE → FOCUS_STATE → OP_BATCH → FOCUS_RESOLVE`。
- App 的专注动作只在匹配的 `RESULT/COMMITTED` 后落地。
- 同一个 ResolveID 不再携带不同 payload 重试，避免设备把两次不同裁决视为同一事务。

## Build 647

Git 范围：`d7fe49c..fda2ed8`  
差异规模：36 个文件，新增 3,574 行，删除 265 行。

### BLE 首次连接状态

- 将一次连接拆成内部阶段：

  ```text
  awaitingLink
  → discoveringServices
  → discoveringCharacteristics
  → enablingNotify
  → handshaking（安全模式）
  → ready
  → cancelling（取消收尾）
  ```

- 物理连接使用独立的 15 秒期限；`didConnect` 后重新获得完整的 15 秒做服务、特征和 Notify 建立。
- `setNotifyValue(true)` 不再等同于连接成功；必须等 `didUpdateNotificationStateFor` 且 `isNotifying == true`。
- 安全模式只在 Notify 确认后发送 `0x7F` 握手。
- 连接计时器、回调和取消操作绑定 connection generation 与外设身份，旧回调不能收掉新连接。
- 取消连接后进入 `cancelling`，等 CoreBluetooth 收尾，减少同一外设的新旧尝试互相覆盖。
- Notify 确认前到达的完整业务消息会暂存，限制为 8 条或 8 KiB；连接 ready 后按顺序投递一次。

### 自动恢复策略

- 每轮最多进行 10 次真实 `manager.connect`。
- 失败等待时间为 `1、2、4、8、15、30、30、30、30` 秒。
- 找到外设后只重连已知外设，不再反复扫描。
- 稳定连接的普通意外断开改用不超时的 CoreBluetooth pending connection，等待设备回到范围。
- 前 9 次建立失败时界面保持连接中，第 10 次失败才显示最终错误。

### DeviceWake 门槛（后来在 Build 648 移除）

- Build 647 把同 generation 的 DeviceWake 当作业务同步开始条件。
- 当连接 ready 后 5 秒仍未收到 DeviceWake，会主动断开与硬件的 BLE 连接并启动已知外设重试。
- 这不是硬件 1.3.1 协议要求，而是 App 新增的恢复策略。它会把“Notify 已建立、但 DeviceWake 稍晚”的健康连接当成失败，是 Build 648 删除的主要对象。

### FocusRevision 与专注恢复

- 新增按外设 UUID 持久化的 FocusRevision 账本。
- `0` 只表示未初始化；第一个有效出站版本为 `1`。
- 同一冻结内容重试复用原 Revision；内容改变后使用 `max(本地, Session, 设备) + 1`。
- 禁止 Revision 回绕到 `0`；达到 `UInt32.max` 后，新状态返回 `revisionExhausted`。
- 普通 `0x14` 与 `FOCUS_RESOLVE` 使用同一账本。
- 账本损坏时不直接从 1 重来，必须先收到有效 `FOCUS_STATE`，再以设备版本为下限恢复。
- 用带所有者的 freeze lease 代替可被任意代码直接开关的单一布尔值。
- 排队中的旧 `0x14` 在真正写入前再次检查 generation、freeze epoch、Revision 和 SessionId。
- 匹配 `RESULT/COMMITTED` 后先应用并持久化专注结果，再释放 OfflineSync 写锁和 freeze lease；公开发送接口不再在持有非重入写锁时重新取锁。

### DeviceWake 断开规则修正

- 删除“连接 ready 后 5 秒未收到 DeviceWake 就主动断开硬件”的看门狗。
- 删除 DeviceWake timeout 专用断连和重连状态。
- 5 秒现在只限制当前同步任务等待多久，不再判断 BLE 连接是否健康。
- 5 秒内没有 DeviceWake 时：结束本轮同步等待、释放本轮写锁和 freeze lease，但保持 BLE 连接。
- DeviceWake 稍后到达时，在同一 connection generation 上发起一次同步，不需要先断开再连接。
- 没有改变 BLE Type、Opcode、字段偏移或帧长度。
