# 设备任务和日程各至多二十条

修订 [0029](0029-send-only-todays-tasks-to-the-device.md) 中「数量不设上限」一句，并连带废除 [0001](0001-send-the-complete-task-library.md) 遗留的同类表述（2026-08-04 客户拍板）。

设备任务库至多包含当天的前二十条任务，顺序即用户在 App 里的列表顺序，不按优先级或截止时间重排。当天内容包至多包含当天最早的二十条日程，按开始时间排序后取前二十。超出的部分不发送，App 也不向用户提示——用户在 App 里看到的仍是全部任务和日程，只是设备上看不到多出来的部分。

上限只约束 App 发送什么，不改变设备的职责：设备收到多少就完整保存多少，不自行计数也不自行截断；一次内容放不下时整次事务失败并保留旧版本，而不是截断后报告成功。

两个后果是这个决定的直接产物，不作为缺陷处理。其一，当天任务多于二十条时，用户在硬件上跳过队首任务，该任务被移到列表末尾后会掉出前二十而从设备上消失——「队尾」就是第二十一位，而设备只能看到前二十位。其二，完成或删除一条任务走的是即时生效的小事务，它只从旧任务库减去被删除的任务、不提拔第二十一条，所以设备会暂时只剩十九条，最多三分钟后由完整事务补齐。

配套实现决定：截断收敛在决定「哪些任务上设备、以什么顺序」的单一函数里，而不是加在编码环节。增量更新因此自动正确——变化前后两侧看到的是同一个截断视图，删掉一条任务时第二十一条的补位不需要额外代码。任务变化跟踪同样使用截断后的口径，否则编辑第二十一条任务会让三分钟稳定窗到期后发出一份没有任何内容变化的新版本。唯一的例外是任务文字的生成与丢弃采用不同口径：不再进入前二十的任务不再生成新文字，但已经准备好的文字不丢弃，这样它重新回到前二十时不必重新生成。wire 字节布局不变。
