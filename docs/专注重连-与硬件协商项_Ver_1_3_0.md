# 专注重连 Ver 1.3.0：待与硬件团队确认

> **已过时。** H1 / H2 / H6 已由 Ver 1.3.1 裁定。请改读 `docs/专注重连-与硬件协商项_Ver_1_3_1.md`。

App 已按 `docs/Kirole_专注状态重连_App对接说明_Ver_1_3_0.md` 与 `docs/Kirole_BLE协议命令字节表_专注重连协议更新_Ver_1_3_0.md` 的固件原文实现。下列条目是协议内部互相打架、或实现后仍不合理的地方，**请硬件团队裁定后改协议或改固件**，不要由 App 单方面猜。

| 编号 | 固件原文 | 问题 | App 当前做法 | 建议 |
|---|---|---|---|---|
| H1 | 对接说明 §4 步骤 7：「设备确认裁决成功且双方版本一致后，解除同步锁定」 | 字节表没有 `FOCUS_RESOLVE` 的应答；`RESULT 0x81` 只用于 BEGIN / COMMIT / ABORT | `FOCUS_RESOLVE` 发出即解锁，随后发普通 `0x14` / `0x11` | 补一帧 `RESULT(TargetType=0x25, SyncID=ResolveID)`，或删掉步骤 7 的「确认后再解锁」 |
| H2 | 步骤 6：「发送 TaskInPage / FocusStatus / DayPack」 | 未写清是普通业务帧还是同一轮 `0x25 COMMIT`。现网固件把 COMMIT 当成离开 TaskIn | 裁决后**不**因专注仍在而强制 COMMIT；只发普通 `0x11` / `0x14` / `0x10` / `0x03`。`NeedsFullSync` / 数据无效 / 过期仍走 COMMIT | 书面确认：active 专注时立刻下发的普通 `0x10` 会不会也踢出 TaskIn |
| H3 | `OperationOverflow + NeedsFullSync`：「执行完整状态核对」 | 溢出表示设备已丢操作。再 COMMIT App 快照可能盖掉无法还原的设备状态 | 仅溢出：ACK 尚存操作，不 BEGIN。两旗同在：按 NeedsFullSync 做 BEGIN→COMMIT | 确认溢出后仍要 App 全量覆盖，还是先停在设备当前页等人工核对 |
| H4 | Schedule Description「不可空，禁止只发标题」 | 日历事件经常没有备注。占位句不是可见日程描述 | 有备注用备注；无备注填 `Details forthcoming.` 以满足 `1≤D≤120` | 允许 `DescriptionLength=0`，或接受占位句为合法 |
| H5 | 「不要使用 `DeviceMode(0x12)` 进入、退出或裁决专注」 | 线上 `EnterTaskIn` 找不到任务时，旧实现用 `0x12 interactive` 解卡。协议没给「未知任务」路径 | 改为发 `0x14 idle`（专注通道），不再用 `0x12` | 确认未知 TaskId 时设备应退回概览，并接受 `0x14 idle` |
| H6 | OfflineSync BEGIN 备注写 `bit2(0x03)：DayPack` | 同表 DatasetMask 节写 `bit2 = 0x04`。`0x03` 是 TaskList+Schedule | App 按 `0x04` 编 DayPack 位 | 改字节表 BEGIN 备注笔误，避免固件按 `0x03` 实现 |
| H7 | 建议模型含 `deviceId / bootSessionId / startSource / lastOperationId` | 这些字段不在 `0x14` 线上，只在 `FOCUS_STATE` | App 会话已持久化这些字段，不另占 wire | 无需改线；确认即可 |

联调时请优先看 **H1（丢包窗口）** 和 **H2（DayPack 是否踢页）**。
